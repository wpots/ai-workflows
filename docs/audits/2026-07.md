# AI Stack Review — July 2026

A full review of `ai-workflows` against the current (mid-2026) ecosystem:
obra/superpowers, gstack (Garry Tan's stack), Every's compound-engineering
plugin and Claude Fable 5 prompt library, the Agent Skills / plugin-marketplace
standards, and public writeups of how frontrunner companies (Anthropic, Ramp,
Shopify, incident.io, Block, Sentry, Atlassian, Vercel) run their AI stacks.

Produced 2026-07-29 from a repo deep-read plus four parallel research tracks.
This file is review input, not a plan: follow-up tasks are listed at the end
for backlog triage. Star counts and self-reported benchmarks are avoided or
hedged; sources at the bottom.

**How to read this:** TL;DR → what's strong → findings (F1–F12) → ecosystem
comparison → frontrunner practices → follow-up tasks (T1–T18).

---

## TL;DR — The Five Moves That Matter

1. **Consolidate Claude distribution on the plugin.** Skills currently reach
   Claude twice (file sync to `~/.claude/skills` *and* the `greenberry`
   plugin) — observable as double skill listings in live sessions — and the
   synced global `CLAUDE.md` on at least one machine is stale. The ecosystem
   verdict is unambiguous (Thoughtworks Radar: marketplaces are the fix for
   copy-paste sync drift). Keep sync only for tools without plugin support.
2. **Add a CI agent lane on GitLab.** Headless MR review and pipeline triage
   are table stakes in 2026, and first-party support exists (official Claude
   Code GitLab CI/CD path; GitLab Duo Agent Platform GA). The repo's CI today
   only runs static validation.
3. **Treat skills like code: evals + budget.** 1 of 29 skills has evals and
   nothing runs them. First-party tooling (skill-creator eval/benchmark modes)
   made this cheap. Every's rule is the target: every failure becomes a test,
   a rule update, *and* an eval.
4. **De-personalize for team scale.** Hardcoded `~/Web/ai-workflows` paths,
   reviewer `wieteke.pots`, and "tickets on the user's name" make this a
   single-person stack. Every's org lesson validates the centralized-repo
   model — but it only compounds for a team once parameterized and owned.
5. **Enforce the loop instead of documenting it.** The improve-skill /
   skill-opportunity / upstream-rules trio *is* compound engineering — but its
   trigger is prose. Frontrunners enforce process with hooks (superpowers'
   SessionStart gate, Anthropic's Stop-hook verification), not with
   instructions the model can skip.

Cross-cutting theme from every frontrunner: **agents verify their own work**
(tests, build exit codes, screenshots, telemetry — evidence, not claims).
Skills here mostly end in a report; they should end in a runnable check.

## What's Already Strong

Credit where due — several things here are *ahead* of most public stacks:

- **Surface architecture with enforcement.** rules = policy, skills =
  canonical workflows, commands = fallback, adapters = routing, plus a
  canonical-sources registry checked by `validate-skills.mjs` in CI and
  pre-commit. Most popular stacks (gstack included) have no equivalent
  anti-drift machinery.
- **The improvement loop exists.** `improve-skill` (with superpowers'
  writing-skills DNA: baseline-must-fail, form-matches-failure),
  `skill-opportunity`, `upstream-rules`, `upstream-to-unicore`. This is the
  "compound" step Every sells — already native here.
- **Full-SDLC breadth.** Sprint ceremonies, refinement, backlog authoring,
  autonomous delivery, review chain, a11y + sustainability audits,
  maintenance. Public stacks cover the code loop; this covers the agency
  delivery process.
- **Governance.** MR-only with named reviewer, enforced by a pre-push hook and
  injected into every adapter. Nobody at the frontrunners auto-merges agent
  code either.
- **Hooks as enforcement at project level.** The synced
  `project-claude-settings.json` already ships a graphify router, a
  `migrate:fresh` deny guard, and sprint-board nudges — the pattern the
  ecosystem now calls "scoped, self-validating hooks".
- **Author-once, emit-per-tool.** `generate-adapters.sh` + shared fragments is
  the same model wshobson/agents productized for multi-harness distribution.

## Findings

### Distribution & Loading

**F1 — Claude gets everything twice (sync + plugin). Resolved 2026-07-29.**
The repo side had already landed on main (`sync.sh` now removes repo-owned
copies from `~/.claude` and README documents the migration); the local machine
was migrated and verified the same day. Original finding kept below for
context.
`sync.sh` copies skills/commands/CLAUDE.md into `~/.claude/`, *and* the
`greenberry@ai-workflows` plugin serves the same skills from the marketplace
clone. Live sessions list every skill twice (`create-pr` and
`greenberry:create-pr`). Worse, sync has no freshness guarantee: the synced
global `CLAUDE.md` on this machine still contains `experimental.*` mappings
that the validator now bans — the plugin channel auto-updates, the sync
channel silently rots. Pick the plugin as the only Claude channel; keep sync
for Codex/Cursor/Roo/Copilot until F-standards (below) collapses those too.

**F2 — The plugin has no version, changelog, or release notes.**
`plugin.json` lacks a `version` field, so every commit to `main` is silently a
release. No CHANGELOG, no release channel, no way for a consumer to pin or to
see what changed. Ecosystem norm is explicit semver + release notes; Every
goes further (release automation owns the version, PRs never hand-bump).

**F3 — The plugin ships the whole repo root.**
`source: "./"` means auto-discovery picks up `commands/` as slash commands
(`/greenberry:create-pr` next to the skill — a third surface for the same
workflow) and packages docs/templates/packages into every install. Decide
whether commands belong in the plugin at all (Copilot is their audience) and
scope the plugin explicitly.

**F4 — Always-on context fails the prune test.**
The command-mapping table is duplicated across global and project CLAUDE.md,
while skill frontmatter descriptions already do the routing on skill-aware
tools. Anthropic's internal rule for CLAUDE.md: for every line ask "would
removing this cause mistakes?" Every's version: "ten specific rules beat 100
generic ones." The stale-copy incident (F1) is direct evidence the table
drifts. Candidate cuts: mapping table (for Claude), duplicated safety prose,
anything a skill description already covers.

### Inventory & Hygiene

**F5 — FEATURES.md is the only unvalidated inventory, and it shows.**
Lists 12 of 29 skills, 9 of 15 commands, misses `sonarqube.md`,
`sustainability.md`, and the react-aria MCP server. `workflow-canonical-sources.md`
stayed correct *because the validator checks it*. Either validate FEATURES.md
the same way or delete it and point at the validated docs (the planned
`docs/pipeline-map.md` covers the by-process view).

**F6 — mcp/servers.json is machine-specific and partly redundant.**
The filesystem server hardcodes `/Users/wietekepots/Web` (breaks for any
teammate) and is redundant inside Claude Code anyway; the GitHub MCP server
overlaps with `gh`/`glab` CLI usage that skills already prefer. Jira/Figma
run through claude.ai connectors in practice but aren't documented here.
*Widened 2026-07-29:* the gap is bigger than stale MCP config. The stack
hard-depends on CLIs (`glab` for watch-mrs/create-pr/MR rule, `jira` for
sprint skills, `dotenvx` for secrets) that no setup doc installs or verifies,
and project-level MCP needs (playwright + chrome-devtools at RFW) live only
in a personal `~/.claude.json` — a second developer gets nothing. See T13
(upgraded to an integration tooling lane).

**F7 — WIP hygiene. Resolved 2026-07-29.**
At review time the checkout was 25 commits behind `gitlab/main` with a dirty
tree; that work has since landed and the tree is clean. Kept for numbering.

**F8 — packages/ has manifests but no consumer.**
Six `package.yaml` presets that no tooling reads (selection sync is an
unfinished branch). Finish the loop or cut the layer; half-built layers cost
credibility and maintenance.

### Quality & Evals

**F9 — Evals: 1 of 29 skills, zero runs.**
`component-spec/evals/evals.json` is a good seed (prompts + assertions) but
has no runner and isn't in CI. In 2026 this is the biggest gap vs. norms:
skill-creator ships first-party eval/improve/benchmark modes (graded outputs,
blind A/B, trigger tuning); Every treats prompt evals as unit tests and has
agents re-run them until stable. Without evals, `improve-skill` edits are
unverified — process changes with no regression net.

**F10 — No skill token budget or profiling.**
`create-pr` (15.5 KB) and `maintenance` (14 KB) load whole; only two skills
use auxiliary files (progressive disclosure). Superpowers 6 cut ~60% of token
cost by measuring and self-optimizing its skills — this repo has never been
profiled. Cheap wins: split reference material into skill-dir files, audit
descriptions, set a size budget in the validator.

### Team Scale & Enforcement

**F11 — Single-person assumptions everywhere.**
Skills hardcode `~/Web/ai-workflows`, the MR rule hardcodes reviewer
`wieteke.pots`, sprint skills scope to "tickets on the user's name". There is
no OWNERS notion, no onboarding path beyond `new-device-setup`, no per-dev
config. Every's org lesson (per-employee agents failed; shared team agents
with centralized maintenance won) says this repo is the right model — but it
only scales once paths come from `${CLAUDE_PLUGIN_ROOT}`/config and people
parameters come from git/tracker identity.

**F12 — The rules that matter most are prose, not machinery.**
The improve-skill auto-run rule, the shell-allowlist autonomy doctrine, and
skill dispatch all live as instructions the model can skip under pressure.
Frontrunner pattern is hooks: superpowers gates every session with a
SessionStart hook; Anthropic's escalation ladder ends in Stop hooks that block
completion until checks pass. Concretely: a Stop hook for improve-skill
(already planned as pipeline-map BLI #9), a shipped `permissions.allow`
baseline in `project-claude-settings.json` so the allowlist doctrine is
config, and optionally a session-start skill-dispatch nudge.

## How Frontrunners Run Their AI Stacks

Condensed to what's actionable; sources at the bottom.

- **Anthropic** — Verification loops as rule #1: give the agent a runnable
  check (tests, build, linter, screenshot-vs-design) and require evidence,
  not claims. Escalation ladder ends in Stop hooks and fresh-context verifier
  subagents. CLAUDE.md treated as code: short, pruned, reviewed. Writer/
  reviewer Claude separation. Reported 80–90%+ of merged code agent-written;
  onboarding = asking Claude questions against the codebase.
- **Every** — Effort split ~80% planning + review, ~20% execution. Compound
  step writes lessons to solution docs future sessions auto-discover. 12+
  parallel review perspectives merged into one P1/P2/P3 list. Five products on
  near-single-person teams.
- **Shopify** — Standardize the layer *under* the tools (central LLM proxy,
  usage analytics); engineers pick their own editor/agent. Reversion-rate
  tracking on PRs; mandatory senior human review; "AI-reflexive" is a
  performance expectation; weekly demos are the metric, not LOC.
- **incident.io** — 4–7 concurrent agents per dev in isolated worktrees behind
  a one-command helper; plan mode as the default confidence gate; CLAUDE.md
  doubles as the new-joiner onboarding doc; next bet: ephemeral per-MR
  environments with fast CI.
- **Ramp** — Background agent (sandboxed VM per session, full stack +
  Sentry/Datadog wired in); agents verify their own work (run tests, read
  telemetry, post screenshots). ~30% of merged PRs agent-authored; adoption
  spread virally through public Slack channels, no mandate.
- **Block (goose)** — Parameterized YAML *recipes* let non-engineers author
  workflows; one binary + recipes dir + MCP dir serves ~60% of 12k employees
  weekly; tracks "manual hours saved" against a 25% target.
- **Sentry** — Three AI reviewers dogfooded on their own repos (Seer, BugBot,
  Warden for convention checks pre-push + CI). Norm: read, apply, dismiss —
  never blind-accept.
- **Atlassian** — AI reviewer pipeline with an LLM-as-judge factual check and
  a nitpick filter; measures comment→code resolution rate (38.7%), PR cycle
  time (−30.8%) — not comment volume.
- **Vercel** — Internal agents built on the open skills standard; migrations,
  on-call debugging, design-system matching live as skills in dedicated mini
  repos with owners; automated security audits on skill distribution;
  non-developers among top skill authors.

**What separates frontrunners (cross-company):** agents verify their own work;
learnings are codified same-day, not remembered; skills/recipes are the
versioned, owned unit of shared workflow; fresh-context AI review on every
PR with a quality filter and resolution-rate tracking; isolated parallel
environments (worktrees/VMs, fast CI); outcome metrics reviewed weekly
(agent-authored MR %, reversion rate, cycle time); a named small team owns the
stack; human review stays mandatory and enablement is deliberate (demos,
office hours, leaderboards — not mandates).

**Fit for Greenberry (agency, GitLab, Next.js/Payload):** adopt verification
loops in skills, the CI review lane, compound/eval discipline, worktree
parallelism (EnterWorktree already exists), per-skill owners, and lightweight
metrics. Skip: in-house background-agent infra and LLM proxies (per-seat
Claude + GitLab CI covers it at this size), fine-tuned comment filters (a
prompt-judge step suffices).
